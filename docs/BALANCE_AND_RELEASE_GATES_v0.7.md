# Девелопер — баланс и аудит исполнимых механик v0.7.0

Дата: 17.10.2026. **Статус:** экспериментальная, автоматизированно проверяемая HTML-версия, не релиз Godot. Не изменяет ключевые утверждённые правила без согласования.

## 1. Подтверждённые факты

Исходники: `index.html` (сборка поля/паспорта/действий/правил) + `balance.js` (ограниченные карты, операции, боты и экономика). Автотест: `tests/smoke.cjs`, workflow `.github/workflows/test.yml`. Источники правил: [RULES_CURRENT.md](./RULES_CURRENT.md), [DECISION_DESIGN_FIRST_v0.5.3.md](./DECISION_DESIGN_FIRST_v0.5.3.md), [DECISION_PROPERTY_NETWORK_BONUS_v0.5.4.md](./DECISION_PROPERTY_NETWORK_BONUS_v0.5.4.md).

**Окончательно закреплённые авторские правила, которые сохранены:** строительство через проектирование → разрешения → строительство → ввод; готовое здание отображается одним типом; инженерные карты вода/газ/электричество/канализация/центральное теплоснабжение, для малого/среднего/крупного требуется 1/2/3 карты; победа при четырёх собственных введённых зданиях, соединённых стороной участка, без диагоналей; отдельные трассы сети между участками пока не моделируются; кредитная кнопка в HTML отсутствует. Числа баланса ниже — **ГИПОТЕЗА**, не считать одобренными пользователем.

## 2. Решения, реализованные в HTML v0.7.0 — балансные гипотезы

| Подсистема | Текущая модель | Верификация |
|---|---|---|
| Строительные карты | 4 × 12 физических экземпляров в общем обороте; 12 индивидуальных смет в колоде | Тест колоды |
| Инженерные карты | 5 типов × 3 физических экземпляра = 15 | Тест колоды |
| Максимум на руках | 8 строительных + 4 инженерных | Код, отдельный UI smoke нужен |
| Расход и оборот | Использованная карта возвращается в доступный запас **после 4 полных раундов**; пустая колода не создаёт новую карту | Тест исчерпания/возврата |
| Сделки между участниками | В свой ход через «Обмен карт»: продажа своей карты боту, выкуп публичной оферты бота, обмен с денежной доплатой; одно договорное действие за ход | Тест покупки, продажи, обмена и защиты от повторного исполнения |
| Цена переговоров | Формируется из базовой сметы и коэффициента дефицита; бот имеет собственные лимиты и доплаты | Временная формула, стратегическая проверка |
| Действия | После броска максимум два основных действия — стройка, инженерное подключение, договорная сделка, назначение арендатора/покупателя, инвестор, госзаказ и прямая продажа; автоматический эффект клетки не считается | Тест запрета третьего действия; требуется ручной UI regression |
| Работа / Старт | Стартовый капитал 600; +60 за пересечение «Старта»; рабочие события 45–101 до бонусов профессии | Существующая исходная модель |
| Аренда | Начисление только при арендаторе и проходе «Старта»; начисление за случайное попадание на постороннюю клетку исключено | Смоук и симуляция |
| Сети и стоимость | +10% от базовой ставки аренды и цены продажи за подходящую сеть; +10/+20/+30% максимум | Тест подключения; баланс Г |
| Инвестор | Привлечение суммы из карты, обязанность вернуть **125%** суммы; при прохождении «Старта» автоматический взнос: минимум 20, либо 8% первоначальной суммы, либо установленная доля аренды — выбирается максимум, но не выше остатка долга | Автотест выплаты инвестору без арендатора пройден; баланс и полные договоры требуют проверки |
| Госконтракт | Принятие/отказ/исполнение: инвестиционный контракт 120→145 через 6 раундов; земельный выкуп до 115% цены, не выше лимита карты; сдача готового малого здания; срок 16 раундов, штраф за просрочку 60 | Автотест принятия и завершения государственного инвестконтракта пройден; земельная и строительная ветки требуют E2E |
| Кризис | Коэффициент базовой продажи и аренды 80–120% по карте на два раунда | Смоук |
| Банкротство | При отрицательном балансе, проверяемом расчётом хода/раунда, потеря активов и оборотных карт с задержкой, старт заново с 120 | Код, проверка UI нужна |
| Боты | Покупка земли на аукционной клетке, выбор недостающего этапа, стройка, инженерные подключения, арендаторы, инвесторы, торговля со сверстниками и консервативные госинвестиции; те же два действия за ход | Бот-турнир |
| Продажа / биржа | Продажа готовых объектов и разыгранные ранее заявки на строительные/рыночные карты сохранены | Предыдущие тесты; комплексный E2E ещё не проведён |

**Блокер реального взаимодействия людей:** собственно торговля **человек-человек** и общий синхронный ход с 3–6 телефонов не реализованы; сейчас доступны сделки человек-бот и бот-бот. Это тестовое приближение к ограниченному рынку, не сетевой мультиплеер.

## 3. Экономический анализ и эксплойты

- Исходный малый объект: базовая продажа 450 тыс., аренда 22 тыс. за один цикл «Старта» при 100% ставке; базовые этапы 35 + 45 + 135 + 30 = 245 тыс., **без земельного участка**. Земля в HTML стоит 120–330 тыс.; полная себестоимость базового малого объекта: **365–575 тыс.** в зависимости от земли и индивидуальной карты (в реальности карта может сделать этап дороже/дешевле). На дорогой земле перепродажа по базовой цене убыточна, а аренда окупает объект со временем. Дефицит земли и необходимость финансирования — намеренный стратегический риск, не подтверждённая окончательная цена.
- Средний базовый объект: 65 + 90 + 290 + 55 = 500 тыс. + земля; базовая продажа 930 тыс., аренда 45.
- Крупный базовый: 115 + 160 + 540 + 110 = 925 тыс., базовая продажа 1720, аренда 86. **Критический конфликт:** в описании крупный требует двух соседних участков, но код пока использует один; оценка прибыли крупного может быть завышена, ДО прояснения правил менять тайно нельзя.
- До исправления договор госзаказа позволял боту автоматически ликвидировать победные объекты: в турнирной серии 5–6 участников часто не было победы к 900 ходам. Автоматическая сдача важных зданий по госзаказу выключена для ботов; люди могут выполнить госзаказ по своему выбору.
- Из первоначального кода удалена скрытая плата «за проход по чужому участку», ошибочно привязанная к несвязанной клетке внешней дорожки. Никакой дополнительной арендной выплаты без арендатора нет.
- Нескончаемые новые экземпляры карт прекращены; введены максимумы склада и задержка оборота. Остаётся риск: после длительного фарма колоды/работы игрок может зарабатывать за счёт продажи карт, не занимаясь девелопментом. Нужны ручные антиэксплойт партии.
- Система инвестора предотвращает бессрочный бесплатный капитал, но требуется моделирование договора при передаче имущества и банкротстве.

## 4. Проверенные автоматические партии (GitHub Actions)

**Отчёт сборки:** [GitHub Actions — Browser game regression tests](https://github.com/bunkovde-lab/developer-web/actions/workflows/test.yml). Smoke: синтаксис JS, исчерпание запасов, возвращение карт, исполнение сделки, запрет двойного выкупа, инженерное улучшение и его денежный эффект, кризис, приобретение земли ботом.

Контрольная серия из 16 игр: **4 случайных seed на каждое число 3 / 4 / 5 / 6**, до 900 суммарных ходов, все игроки — боты, единая тестовая экономическая политика. **16 из 16** завершились достижением победы, без исключений JavaScript. Результаты после ограничения ботов двумя действиями за ход:

| Участников | Побед / партий | Мин. ходов до победы | Медиана ходов до победы | Макс. ходов | Эпизодов исчерпания запасов, сумма 4 партий | Торговых операций бот-бот, сумма 4 партий |
|---|---:|---:|---:|---:|---:|---:|
| 3 | 4 / 4 | 299 | 401 | 514 | 0 | 29 |
| 4 | 4 / 4 | 400 | 489 | 511 | 14 | 32 |
| 5 | 4 / 4 | 444 | 582 | 611 | 43 | 22 |
| 6 | 4 / 4 | 421 | 597 | 699 | 88 | 30 |

Эти значения — **суммарные ходы всех игроков**, а не ходы одного участника. Исчерпание означает попытку добора карты, пока весь запас распределён между руками и задержкой возврата. Торговые операции между ботами существуют, но обязательность переговоров между людьми не подтверждена.

Проверка длительности пока только аналитическая: при **условных** 30 сек на ход медианы дают ~3,3 / 4,1 / 4,9 / 5,0 часов для 3 / 4 / 5 / 6 участников. При 45 сек будут ~5 / 6,1 / 7,3 / 7,5 ч — слишком долго. **Реальная скорость человеческого хода и партии не измерялись; цель 3–5 ч не подтверждена.**

## 5. Открытые конфликты и ограничения (приоритеты)

**P0 — нет сетевого мультиплеера**, в том числе человек-человек сделки и приватные карты на телефонах. **P0 — несоответствие нативному Godot:** `Game-boar/scripts/developer.gd` пока другой простейший вертикальный срез (24 участка, три действия, кнопка кредита), а `developer-web` — HTML 30 участков, два действия и без кредитной кнопки. Они не совместимы автоматически. **P0 — Godot/APK для этой версии не собран и не испытан.**

**P1 — законность двух участков** для крупного комплекса; **P1 — финансовая модель инвестора** (договор vs простой долг), залог при продаже/банкротстве, права на инженерные сети; **P1 — редкие кризисы и госзаказы** требуют больше сценарных тестов; **P1 — отдельные стратегии ботов** (сейчас преимущественно один алгоритм с отличающимися доступными карточками); **P1 — воспроизводимость автосохранения старых партий в реальном мобильном браузере**, UI/UX, FX, звук.

## 7. Критерий релиза

Нельзя назвать игру «полностью готовой», пока нет: успешных Godot импортов и Android экспортов, устанавливаемого проверенного APK, приватной LAN-партии с 3–6 людьми/ботами, всех утверждённых реализованных подсистем без заглушек, ручных прохождений 3–5 ч и документированного контроля баланса/эксплойтов по нескольким стратегиям, а также визуального и звукового QA.

**Следующий проверяемый шаг:** прогнать ручную браузерную партию после обновления и проверить рынок «Обмен карт» + 2 действия/ход, а затем перенести ограниченную модель в Godot по Issue #8.
