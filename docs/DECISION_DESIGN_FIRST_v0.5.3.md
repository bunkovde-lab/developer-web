# Решение: «Проектирование» — первый строительный этап (17.10.2026)

Статус: **утверждено; реализовано в HTML-игре; пройдены изолированные проверки кода**.

## Новая последовательность
1. **Проектирование** (внутренний ID `utilities` оставлен без изменений для совместимости карт и сохранений).
2. **Разрешения** (`permits`).
3. **Строительство** (`construction`).
4. **Ввод в эксплуатацию** (`commissioning`).

Этапы оплачиваются при использовании соответствующей карты. Цены каждой карты и все существующие расчёты не меняются. Полностью готовый объект остаётся в статусе `project.stage === 4`. Условие победы (четыре собственных завершённых здания на соседних по сторонам участках) не меняется.

## Совместимость прежних партий
Предыдущая последовательность начиналась с разрешений. Если в сохранении объект имел `project.stage === 1` без поля `order`, он уже прошёл разрешения, поэтому следующим разрешённым этапом по-прежнему будет проектирование. Новые объекты сохраняют `project.order='design-first'`, чтобы после перезагрузки, при `stage===1`, следующим требовались разрешения. Продолжения старых объектов получают `order='legacy'`. Стадии 2–4 общие для обеих последовательностей.

## Не изменяется
- Три клетки поля «Инженерные сети» и отдельная колода карт: вода, газ, электроэнергия, канализация, центральное теплоснабжение.
- Набор 12 карт бывшей инженерной строительной колоды (теперь подписанной «Проектирование»), их временные сметы и свойства.
- Логика аренды, продажи, аукционов и победы; отдельные физические линии сетей не требуются.

## Контроль
Подтверждено проверкой синтаксиса JavaScript и изолированными сценариями: новая стройка через четыре этапа; запрет неочередной карты; отсутствие изменения оплаты; переход готового объекта в стадию 4; возобновление старой партии со стадией 1; загрузка новой партии со стадией 1; сохранение поведения старой стадии 2.

Не проводился полный прогон опубликованной браузерной игры на телефоне. Перед релизом требуется ручной smoke-тест и тест автосохранения.

Это решение заменяет порядок этапов, указанный в `docs/DECISION_STAGE_DESIGN_v0.5.2.md`, но не отменяет его положения о сохранении прежней логики самих карт.
