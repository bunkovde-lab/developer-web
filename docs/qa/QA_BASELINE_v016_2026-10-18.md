## Три самых слабых звена
1. Двойная регистрация проектов ботами — ускорение карьерной победы и завышение итогового балла.
2. Неучтённое требование инвестора к незавершённому проекту в итоговой оценке.
3. Повторная компенсация профессиональных скидок ботам и неправильная себестоимость.

## Три сильных конструктивных решения (не оценка по качеству)
1. Лимитированная земля + связные строительные цепочки стимулируют конкуренцию.
2. Четыре строительных стадии и конечные карты создают основу для обмена ресурсами.
3. Три пути завершения: территориальный, девелоперский, муниципальная итоговая оценка.

## Пять первоочередных действий Programm
1. Интегрировать единственную точку учёта завершения проекта (для человека и бота).
2. Начислять скидку по профессии ровно один раз, стоимость проекта считать по чистому денежному расходу.
3. Исправить учёт обязательств инвесторов при финальной оценке недостроя.
4. Устранить повторный учёт выручки от продажи инвестиционных объектов.
5. Перенести регрессионные тесты финансов, 3–6 игроков, сохранений и ресурсных инвариантов в CI.

У Programm уже существует отдельная ветка `integration/finance-correctness-v017`, содержащая изменения финансовой логики. Эти правки **не слиты в baseline main**. Перед новым патчем проверить интеграционный diff и избегать параллельных конфликтующих исправлений.

## Воспроизводимость

`QA_GAMES=1000 node tests/qa-mass-campaigns.cjs` — 250 seed на размер 3/4/5/6 игроков (в сумме 1 000), базовая версия движка без изменения параметров. Скрипт выполняет реальные вызовы `bot();endTurn();`, использует `node:vm`, исходный HTML inline engine и JS расширения (без визуального слоя), фиксированный LCG. Фиксируются: % завершений, mean/median ходов, причины победы, итоговые деньги, банкротства по событиям, сделки ботов, продажи активов, исчерпание карт, победы по профессиям.

**Ограничения:** все участники запускаются как боты одинаковой базовой политики; смена роли человека на бота в тесте нужна для полного автоматического хода. Тест не подтверждает отдельную доходность стратегий аренды/продажи, серверные многопользовательские переговоры, реальную длительность в часах, корректную работу на реальном Android и восстановление сохранений. Собственных движковых **завершённых** массовых партий по этой новой ветке нельзя заявлять без фактического вывода CI.

**Подтверждённые регрессии относительно предыдущего экономического кода:** нет — игровые blob SHA совпадают. **Нерешённые унаследованные дефекты:** четыре финансовые ошибки выше.

## Релизное решение

**Не выпускать как сбалансированную коммерческую игру.** Дождаться исправления финансовых инвариантов, затем повторить массовые JS-прогоны на том же наборе seed и ручной плейтест. QA PR служит измерительным стендом и документом, а не предложением новых правил.
