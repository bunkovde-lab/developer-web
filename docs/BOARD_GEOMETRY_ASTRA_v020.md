# Актуальная геометрия игрового поля — v0.20 candidate (Astra layout contract)

**Статус:** кандидат на фиксацию после приёмки планшетного интерфейса. Это изменение исключительно геометрии HTML. Предшествующий релиз HTML `v0.18.1-rc1`, `main` SHA `9de457274d0ee2931632a93931ba00a039e9e988`. Не изменяются правила, экономические коэффициенты, колоды, 266 исходных SVG, соседство земель или порядок ходов.

## 1. Развёртка

**Модель поля: 11 колонок × 7 рядов**, абсолютное отношение ширины к высоте поля **11:7 (1,57143)**. Для арта эталонный холст `1408 × 896` условных пикселей (модуль клетки `128 × 128`).

- **Контур:** 32 клетки, индексы `0..31`, **без изменения** индексной последовательности движка. Приоритет экрана — landscape Android.
- Клетки `0..10`: верхняя сторона (строка 1, колонки 1→11).
- Клетки `11..16`: правая сторона (колонка 11, строки 2→7).
- Клетки `17..26`: нижняя сторона (строка 7, колонки 10→1).
- Клетки `27..31`: левая сторона (колонка 1, строки 6→2), далее `0 = Старт`.
- **Центр:** grid `columns 2..10`, `rows 2..6` — **9×5 модулей**, в эталонном SVG (`x=128..1280, y=128..768`), 1152×640.
- **Земля:** настоящие 24 участка, существующий `row-major` массив 6 колонок × 4 ряда. Индексы `0..23` не переопределяются. Соседство остаётся `neighborsBySide` игрового движка.
- **Размер условного слота участка:** 1152/6 = 192 × 640/4 = 160, соотношение **6:5** до вычета фасадных зазоров; не квадрат. Не рисовать тайлы под новую карту 30 участков.
- **Существующие SVG:** прежние 266 art keys и `assets/svg/manifest.json` не изменять. CSS показывает SVG в новых слотах; перевод artwork в новый профиль выполняется Astra отдельно.

## 2. Разметка графики для Astra

| Сущность | Логический размер | Размер исходника для Astra | Безопасная зона |
|---|---:|---:|---|
| Общее поле | 11×7 модулей | SVG `viewBox="0 0 1408 896"` | Бордюр и внешнее поле `≤ 2%` |
| Одна клетка дорожки | 1×1 модуль | SVG 320×320 | Текст/символ внутри 8% от краёв |
| Внутренняя территория | 9×5 модулей | SVG 1152×640 (или масштабированный viewBox) | Рамки/дороги вдоль границ |
| Участок | 6:5 (горизонтальный) | SVG 384×320 | Номер/тип в верхней полосе 12%, состояние в нижней 16% |
| Здание/строительная стадия | Контент внутри слота участка | отдельные SVG-слои с прозрачным фоном | Не перекрывать 12% сверху и 16% снизу |
| Дороги/инженерные сети | Между участками, поверх фона территории | векторный слой общей карты | Не перекрывать hit-area кнопок |
| Отметка владельца | низ/рамка участка | CSS переменная `--owner` и SVG-transparent border | Цвет компании читаем на графите |

**Приоритет:** номер участка, цвет владельца, стадия строительства, местная категория, наличие инженерных сетей, подсветка стратегической цепочки. Графика Astra может заменять SVG, но должна сохранить **контракт DOM**: `#board > .cell[data-track-index]`, `.city-map > .city-lots > .map-plot` в исходном порядке. События `developer:visual-event`, `DeveloperMotion`, существующие sprites/stages остаются стабильны.

**Интерфейсные параметры:** рекомендуемый безопасный отступ внутри поля 6–10px (в реальном браузере responsive clamp), зазор между внешними клетками 2–4px, между участками 2–6px. Не размещать сверхважные органы управления на поле или поверх его внутренней дорожки. Отдельные диалоги лежат выше по z-index, анимация пешки ниже диалогов. Следующий пакет Astra — **новый artwork**, а не изменение layout/правил.

## 3. Планшет и телефон

- `1024×768`, `1366×900`: поле слева, кабинет справа, 11:7 без растяжения.
- `844×390` landscape: поле слева, узкий кабинет справа; разрешена вертикальная прокрутка для доступа к действиям, без уменьшения отношения сторон.
- `768×1024` portrait: поле занимает ширину, кабинет ниже, без горизонтального скролла.
- `390×844` portrait: **внешняя область поля фиксируется на 660px ширины и прокручивается пальцем горизонтально**; иначе 11 клеток по `≥44px` физически не уместятся на 390px экране. Масштаб сюжетных клеток не уменьшается, доступна кнопка увеличения города. Общая страница не должна иметь горизонтального переполнения.
- Доступность: опознаваемые 32 aria-label внешних клеток, все 24 участка остаются кнопками; zoom доступен через `#v10Zoom`; текущая позиция и визуальное ожидание события сохраняются.

## 4. Тур и события

Поле изменяет **только** DOM-позиции отображения: индекс ходов 0..31, бросок 2d6, бизнес-состояние, права на участки и порядок колод не меняются. Пешка проходит клетки по контуру 31 → 0; `scene-motion.js` вычисляет маршрут по реальным центрам клеток, поэтому геометрия меняется без дополнительной математики. Карта/аукцион/биржа остаются невидимыми до финальной остановки; отключение анимации немедленно открывает событие.

Прогресс `завершённые ходы / лимит` отображается в компактном поле `#turnProgress` кабинета, значение только читается из `state.completedTurns` и `state.turnLimit`. Дополнительного статус-бара над полем нет.

## 5. Приёмочные тесты и изображения

`tests/browser_rectangular_geometry.cjs` проверяет в Chromium 390×844, 768×1024, 1024×768, 1366×900, 844×390: все 32 координаты и hit-test каждой клетки, 24 фактических parcel-диалога, min 44px площадь касания, геометрия без растяжения и глобального скролла, все 56 SVG привязок (32 дорожки + 24 земли), бесшовный переход 30 → 2 через старт, появление события только после приземления и zoom.

**Скриншоты:** автоматический браузерный тест записывает `ui-snapshots/geometry-v020-<W>x<H>.png` (полная страница) и `ui-snapshots/geometry-v020-board-<W>x<H>.png` (поле отдельно), прикрепляет к GitHub Actions **Browser game regression tests** как artifact `developer-v010-screenshots`. Исторические screenshots HTML v0.18.1 с идентичными разрешениями доступны в предыдущих артефактах `browser-ui`; сравнение допустимо только для схожих DPI/zoom. Скриншоты других PR не считаются новой геометрией.

**Фиксация:** только после успешных CI, визуального осмотра всех 5 скриншотов и пользовательской приёмки на планшете. Затем художественное производство Astra может использовать приведённые размеры без изменения layout.
