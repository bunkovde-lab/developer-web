# Девелопер 0.27 — комнаты по ссылке

Онлайн-оболочка использует экономику 0.26 без смены баланса. От 3 до 6 живых игроков. Создатель запускает партию после подключения всех участников. Ботов в сетевой комнате нет.

## Как играть

1. Откройте игру, укажите имя и профессию, нажмите «Создать комнату».
2. Нажмите «Ссылка» и отправьте её друзьям. Они входят с собственных устройств или браузеров.
3. Дождитесь 3–6 участников и начните партию.
4. Верхняя строка сообщает, кто принимает текущее решение. На торгах это может быть другой игрок, а не владелец текущего хода.
5. «Переговоры»: выставите собственные карты/объекты в витрину, предложите обмен или продажу. Второй игрок должен подтвердить сделку. Положительная доплата означает платёж автора предложения, отрицательная — платёж получателя. Предложение истекает в конце хода автора.
6. После обновления страницы место восстанавливается в том же браузере. Ключ места не входит в ссылку-приглашение.

Комната доступна 30 дней с создания. Если игрок отключился, остальные ожидают его решения: автоматического паса, передачи места чужому игроку и замены ботом нет. Не очищайте данные браузера до завершения партии. Перенос места между устройствами пока отсутствует. Комнаты GitHub Pages и основной версии имеют отдельные ключи устройства; продолжайте с того же адреса, на котором начали.

## Архитектура

- GitHub Pages: статические HTML/JS/SVG; CORS разрешён только для `https://bunkovde-lab.github.io` и собственного origin сервера.
- Sites / Cloudflare Worker: `/api/rooms`, серверная проверка правил и очередь решений.
- D1: одна JSON-запись комнаты с ревизией. Обновление через compare-and-swap `WHERE revision = ?` предотвращает двойные ходы. Повтор последних 64 команд с тем же requestId не применяет действие заново.
- Каждое устройство получает 192-битный случайный ключ места. В базе сохраняется только SHA-256 ключа; в ссылке ключа нет. Все игровые HTTP-ответы имеют `Cache-Control: no-store`.
- Клиент получает только свою руку, количество карт чужих рук и явно выставленные предметы. Порядок колод, генератор случайности и нераскрытые ставки не передаются.
- Серверный движок компилируется из действующих правил. Он не принимает загруженное клиентом состояние или произвольный JavaScript. Генерация происходит при сборке; `eval` и `node:vm` в Worker не используются.
- Обновление состояния — опрос раз в 1,8 секунды, после команды сразу. Это пошаговая синхронизация, не WebSocket.

## Воспроизведение

```sh
corepack pnpm install --frozen-lockfile
node scripts/prepare-online.cjs
node tests/online-v027.mjs
node tests/renewal-v026.cjs
```

Сборка для GitHub Pages: `node scripts/build-site.cjs --out site`. Workflow `pages.yml` публикует актуальный клиент в корень и сохраняет прежние ссылки `/previews/v018/`, `/previews/v0181-rc1/`, `/previews/v019/`, `/previews/v020-qa/` как архивные версии.

Серверная сборка — стандартный Sites/Vinext workflow. D1-схема в `db/schema.ts`, миграции в `drizzle/`. Публичный сервер обязателен для доступа с GitHub Pages; GitHub Pages сам по себе серверные правила и базу не исполняет.

## Проверено

- 21 сетевой сценарий: создание/вход, 4 человека, скрытие рук и колод, очередь действий, стройка, закрытые ставки, единственный участник аукциона, кратность ставки, публикация предметов, согласие на сделку, обмен, запрос города, торги при банкротстве, очередь штрафов, 200 последовательных ходов через сериализацию, одновременные записи, идемпотентность, восстановление места и защита имени от HTML.
- 30 сценариев действующей экономики 0.26; 492 SVG; презентационный слой не изменяет правила.
- В браузере: четыре независимые тестовые личности, создание комнаты, запуск, бросок, продажа карты с подтверждением, закрытый аукцион с четырьмя решениями и покупкой участка, завершение хода и восстановление после перезагрузки. Это функциональная проверка, не четыре физических устройства или длительный нагрузочный тест.
